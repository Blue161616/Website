First-time setup — register the read-only app (one time, ~2 min)

This tool is a static page that talks to Microsoft Graph as you. It needs a single-tenant app registration in your tenant so Entra ID knows to trust this page as a sign-in client. It's read-only — no secrets, no backend. Run the PowerShell below (needs the Microsoft.Graph.Applications module and a privileged role to consent), then paste the Application ID it prints into the field above.

Change $RedirectUri to wherever you host this file. For local testing, host it over http://localhost:<port>/device-discovery.html and use that exact URL.

Prefer the portal? Create an app registration → Single tenant → add a Single-page application redirect URI equal to this page's URL → under API permissions add the delegated Microsoft Graph scopes below → Grant admin consent. Verify a sign-in token in jwt.ms carries the scp claims you expect.

Only User.Read and Device.Read.All are required. The rest are optional — each unlocks a column or a device class, and the tool degrades cleanly (shows "not read") when a scope isn't granted. Least privilege: grant only what you want this tool to see.

What it reads, and how (privacy)

Everything runs in your browser. Each call goes straight from your machine to graph.microsoft.com, authorised by a token MSAL holds in sessionStorage (gone when you close the tab). No data is sent anywhere else and there is no server.

Defender device data is read through Microsoft Graph advanced hunting (/security/runHuntingQuery) because the Defender REST API has no CORS and can't be called from a browser. The hunting queries are read-only KQL over DeviceInfo, AlertInfo, DeviceTvm* and ExposureGraphNodes.

The only optional outbound call to a non-Microsoft host is disabled by default and not used by this tool.
