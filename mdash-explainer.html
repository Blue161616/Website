Codename MDASH, agentic code scanning in Defender

ManagementMDASH is the AI system Microsoft uses to find exploitable vulnerabilities in its own code, now offered to customers as a preview inside Microsoft Defender. More than a hundred AI agents read your source code, argue about each suspected flaw, and report the ones they can stand behind. Your developers get fewer, better findings, and your security team sees them next to the rest of your exposure.

TechnicalMDASH (Multi-model Agentic Scanning Harness) ranks source files by risk, runs 100+ vulnerability-class auditor agents over them on an ensemble of models hosted in your own Microsoft Foundry resource, validates candidates with taint analysis and multi-model debate, and publishes deduplicated findings with severity and confidence to Exposure Management. Scans run remotely through GitHub or Azure DevOps connectors, or locally and in CI/CD with the Defender CLI.

01 · Why it exists

Vulnerability discovery now runs at AI speed

Attackers already point AI at source code to find exploitable bugs. Defenders need the same depth, without burying developers in alerts they cannot trust.

Pattern matching is noisy

Rule-based static analysis flags every pattern that might be dangerous. Teams learn to ignore the output, and the real bugs hide in the noise.

Logic flaws escape rules

Authentication bypasses and logic errors don't match a signature. Finding them takes reasoning about how the code is meant to work.

One model is not enough

A single model hallucinates and has blind spots. MDASH has independent models check each other before anything reaches a developer.

Before: rules in, alerts out

A pattern engine reports everything that looks risky. Developers triage by hand and the real bugs get lost.

03 · What you get

From source code to a fix on a branch

MDASH finds and explains. It never changes your code or environment on its own: fixes are proposed for developers to review.

Deeper detection

Zero-days and logic flaws that pattern matching misses.

  • Not signature-based; informed by past CVEs and patches
  • Memory safety, injection, auth bypass and more
  • Works on source code, not binaries

Confidence you can sort on

Every finding has a severity and a confidence level.

  • Critical, High, Medium, Low
  • Likely, Suspect, Unlikely
  • AI triage: act now, investigate, or defer

Fixes for developers

defender fix drafts code changes from the scan results.

  • Function-level fix on a new branch
  • Uses the GitHub Copilot CLI
  • Developers review and merge

One place in Defender

Findings land in the Exposure Management initiative.

  • Agentic code security score and trend
  • Hotspots by repository, file and weakness
  • Last 90 days of scans, exportable

Fits the developer flow

Scan where the code already lives.

  • GitHub and Azure DevOps connectors
  • Defender CLI on Windows, macOS, Linux
  • SARIF output and an agentic SKILL for AI coding tools

Your models, your region

Inference runs on a Foundry resource in your subscription.

  • You see token use per model
  • Optional MAI-Cyber-1-Flash configuration
  • Results stay in your Defender XDR region
04 · How findings are triaged

Severity × confidence = what to do next

The initiative sorts every finding into one of three buckets. Click a cell to see where it lands.

Rows are severity, columns are the AI's confidence that the finding is real.

Validated by AI scanner

Confident the finding is real, and severe enough to matter. Act now: fix it or hand it to a developer.

Flagged for review

High severity, but the AI couldn't fully validate it. Pause: a human should investigate before acting.

Low priority

Low or medium severity, however confident. Safe to defer or mute.
