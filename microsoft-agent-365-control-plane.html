01

The big idea in one paragraph

start here

For years, Microsoft's security stack governed humans and apps. AI agents are a third kind of actor — they log in, hold permissions, read data, and take actions autonomously — but until now they had no consistent identity, no inventory, and no guardrails. Agent 365 is Microsoft's answer: a control plane that gives agents the same lifecycle management an employee gets, and plugs them into the identity, security, and compliance tools your SOC and IT teams already use.

WHY NOW

Agent sprawl is the new shadow IT

Agents are created in many tools and can act with real permissions. Without a registry you can't answer "how many agents do we have, who owns them, and what can they touch?"

THE MOVE

Agents become first-class identities

Each agent gets an Entra Agent ID — a directory identity like a user or service principal — so existing access, Conditional Access and audit machinery applies to it.

THE PAYOFF

One pane, familiar engines

No new security silo. Agent 365 orchestrates Entra, Defender and Purview so agents are inventoried, least-privileged, watched at runtime, and blocked from leaking data.

03

Microsoft's three pillars

Observe · Govern · Secure

This is the official framing on Microsoft Learn — a useful mental model before the product detail. Each pillar answers a different admin question.

PILLAR 01 · "WHAT'S HAPPENING?"

Observe

Real-time visibility into the agentic environment so admins can spot performance or risk signals early.

  • Centralized Agent Registry — adoption, activity, health
  • Agent Map — connections between agents, users & resources
  • Role-specific views for IT, security & business leaders
PILLAR 02 · "IS IT ALLOWED?"

Govern

Consistent guardrails via lifecycle management, access control and compliance across the enterprise.

  • Intentional agent lifecycle from the M365 admin center
  • Right permissions, policies & access reviews via Entra
  • Audit-readiness & policy alignment via Purview
PILLAR 03 · "IS IT SAFE?"

Secure

End-to-end protection extending Microsoft's identity, data and threat-defense across every agent.

  • Entra — risk-based access for users & the agents acting for them
  • Purview — information protection, DLP & data-risk safeguards
  • Defender — continuous detection, block unsafe behavior at runtime

Who is this agent, and what is it allowed to touch?

Microsoft Entra — identity & access for agents

Entra makes an agent a real directory identity instead of an anonymous script. Once it has an Agent ID, every access decision, policy and audit trail you already run for users and workloads applies to it — including risk-based Conditional Access that can block a compromised agent mid-session.

Entra Agent ID identity

Each agent gets a first-class identity in the directory — discoverable, ownable, and lifecycle-managed like an account. This is the anchor everything else hangs off.

Least-privilege access scope

Agents are granted only the resources they need via app roles & scoped permissions — no more standing broad access "just in case."

Risk-based Conditional Access policy

Adaptive policies react to real-time risk signals and can quarantine or block an agent that's compromised or behaving anomalously.

Access reviews & lifecycle govern

Recertify what agents can reach and retire access when an agent is decommissioned — closing the dormant-permission gap.

Admin surface: Microsoft Entra admin center — Agent ID inventory, Conditional Access, access reviews.
Is this agent behaving — or has it been turned against us?

Microsoft Defender — threat protection for agents

Defender watches agents the way it watches endpoints and identities: continuous detection and real-time runtime protection. It catches known and emerging agent threats — prompt-injection, tool misuse, malicious or unsafe actions — and raises them as investigable incidents inside the same XDR console your SOC lives in.

Real-time runtime protection block

Unsafe or malicious agent behavior is detected and blocked while it happens during runtime — not just flagged after the fact.

Threat detection detect

Surfaces known and novel threats targeting agents — e.g. prompt injection, data-exfiltration attempts, abnormal tool use.

Incidents & investigation XDR

Agent alerts correlate into Defender XDR incidents alongside identity, endpoint and cloud signals, so analysts investigate in one place.

Respond rapidly respond

Rich context lets teams contain a compromised agent fast — feeding Security Copilot and Sentinel for response at scale.

Isolated runtime contain

Agents execute inside Microsoft Execution Containers — a policy-controlled, isolated runtime built on Windows platform security primitives, so a compromised agent is contained by design.

Admin surface: Microsoft Defender portal (XDR) — real-time agent protection during runtime via Defender for Cloud Apps.
Is sensitive data safe when this agent reads, processes or shares it?

Microsoft Purview — data security & compliance for agents

Agents read and generate data — which is exactly where oversharing and leakage happen. Purview gives visibility into AI-related data risk and enforces the same information-protection and DLP controls on agents that protect your documents and chats, plus the audit trail compliance teams need.

DSPM for AI visibility

Data Security Posture Management surfaces where agents touch sensitive data and where exposure or oversharing risk sits.

Data Loss Prevention prevent

DLP policies stop agents from processing or leaking sensitive information — the guardrail against an agent quietly exfiltrating data.

Information protection label

Sensitivity labels & encryption follow the data an agent handles, so protection travels with the content.

Compliance & audit audit

Insider-risk signals, audit logs and compliance assessments keep the agent estate audit-ready and policy-aligned.

Admin surface: Microsoft Purview portal — DSPM for AI, DLP, information protection, insider risk, audit.
05

Five capabilities you'll hear named

the product vocabulary

Marketing and docs describe Agent 365 through five capability areas. Here's the plain-English version so the terms don't trip you up.

CAPABILITY 01

Registry

The single source of truth for your agent estate — including Entra-registered agents, Teams Store agents, and shadow agents you can quarantine. Backed by the Entra registry. Registry Sync (public preview, May 2026) pulls in agents across multicloud.

CAPABILITY 02

Access

Managed through Entra with unique Agent IDs and policy templates — least privilege by default, plus adaptive, risk-based policies that respond to real-time risk and block compromised agents.

CAPABILITY 03

Visualization

The Agent Map plus role-based dashboards, analytics, performance metrics and compliance logging — a complete map of connections among agents, users and resources for data-driven decisions.

CAPABILITY 04

Interoperability

Agents reach org data through Microsoft 365 apps and Work IQ, and deploy across Microsoft tools, open-source frameworks and partner clouds — built with Agent Builder, Copilot Studio, Foundry, the Agent Framework, or the Agent 365 SDK.

CAPABILITY 05

Security

Delivered via Defender + Purview: Defender detects threats and investigates incidents; Purview identifies data-exposure risk, prevents leakage, and monitors risky agent behavior for compliance readiness.

HOW TO REMEMBER

Registry sees it · Access limits it · Map shows it · Interop connects it · Security defends it

Five words map to five capabilities — and all of it is enforced by the three engines from section 04.

06

An agent's lifecycle through the control plane

create → retire

Follow a single agent from birth to retirement to see which engine owns each stage.

Build

An agent is created in Agent Builder, Copilot Studio, Foundry, the Agent Framework, or bought from a partner. The no-code tier is where the most agents appear, and where the maker is least likely to be thinking about governance.

owner: Builder tools
Identity

Agents built in Copilot Studio and Foundry are issued an Entra Agent ID and an owner as they are created — a directory identity before anything governs them. Coverage is not uniform: lightweight declarative agents (Agent Builder) have historically run under the invoking user's identity and permissions rather than one of their own. Verify per builder — this is exactly the gap the registry exists to surface.

owner: Entra
Register

Agent 365 registers it into the central registry — and discovers what arrived without an identity: shadow and partner agents, which are issued one here.

owner: Agent 365 registry
Access

Least-privilege scopes and risk-based Conditional Access define what it may touch.

owner: Entra
Operate

Defender protects it at runtime; Purview guards the data it reads & produces.

owner: Defender + Purview
Retire

Access is reviewed & revoked, identity decommissioned, audit trail retained.

owner: Entra + Purview
07

Key terms, decoded

glossary
Control plane
The management layer that sees and governs the whole agent fleet — as opposed to the data plane where agents actually run and do work.
Entra Agent ID
A first-class identity in Microsoft Entra assigned to an agent, so it can be authenticated, authorized, audited and lifecycle-managed like a user or service principal.
Agent Registry
The inventory / source of truth listing every agent, its owner, identity, access and health — including unmanaged "shadow" agents.
Agent Map
A visual graph of connections among agents, users and resources — the "who can reach what" picture.
Registry Sync
Multicloud capability (public preview, May 2026) that pulls agents from other clouds into the Agent 365 registry.
DSPM for AI
Purview's Data Security Posture Management view focused on AI/agent data exposure and oversharing risk.
Runtime protection
Defender detecting and blocking unsafe or malicious agent behavior live, while the agent executes.
Work IQ
The organizational knowledge layer that lets agents reason over Microsoft 365 data and context.
