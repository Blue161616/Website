2
API permissions

Microsoft Graph → all Delegated. Every one is read-only.

Microsoft GraphPolicy.Read.All the cross-tenant access policy — required
Microsoft GraphCrossTenantInformation.ReadBasic.All names partner tenants instead of listing GUIDs optional
Microsoft GraphUser.Read.All correlate guests to partner tenants optional

Only the first is required. Without the second, partners are listed by tenant ID and the report says so — every finding still fires, because the policy is what is being read, not the names. Where a partner has cross-tenant synchronisation configured its display name arrives with that object anyway. Without the third, guest correlation reports itself unevaluated rather than showing zero guests.

In the portal the delegated list sorts CrossTenantInformation directly after Contacts. If it is genuinely absent from your tenant's picker, skip it — nothing here depends on it.

3
Admin consent

All three require it. Adding the permissions is not the same as consenting to them — a Global Administrator has to consent tenant-wide before any call returns data. The Grant admin consent button above opens that screen.

4
Tenant access — consent alone grants nothing

A delegated token acts as the signed-in user, so the account needs a role that may read the policy. Microsoft supports these, and they are not equivalent:

  • Global Reader, Security Reader or Security Administrator — read everything this tool needs.
  • Global Secure Access Administrator and Teams Administrator — read partner configuration but not cross-tenant synchronisation. Signed in as one of those, the sync column reports itself unreadable and a finding says so, rather than reporting that no partner can provision users into your directory.

Global Reader is the least that produces a complete report.

5
What this reads, and what it does not

Only the cross-tenant access policy as Graph returns it: the default configuration, the per-partner overrides, and cross-tenant synchronisation. Nothing is written.

  • It does not simulate sign-in. There is no effective-access evaluation here, so nothing is claimed about what a given external user would be permitted at runtime.
  • A partner setting of null is reported as inherited, never as blocked — inherited from a permissive default is permissive.
  • Tenants with no partner entry are governed entirely by the default, which is why the default is reported first and in full.
