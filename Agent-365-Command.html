First-time setup — register the read-only app (one time, ~2 min)

This tool talks to Microsoft Graph as you. It needs a single-tenant app registration so Entra trusts this page as a sign-in client. Read-only — no secret, no backend. Run the PowerShell below (needs the Microsoft.Graph.Applications module and a role that can consent), then paste the Application ID it prints above.

Change $RedirectUri to wherever you host this file (for local testing, serve it over http://localhost:<port>/Agent-365-Command.html and use that exact URL).

Only User.Read and ThreatHunting.Read.All are required (the agent inventory). The rest are optional — each adds owners/sponsors, blueprints, licence context or CA posture, and the tool degrades cleanly to "not read" when a scope isn't granted.

What it reads, and the one thing it can't (honesty)

Everything runs in your browser against graph.microsoft.com. The agent inventory is the Defender advanced-hunting AgentsInfo table (every platform — Copilot Studio, Foundry, Agent Builder, M365 Copilot, third-party and endpoint-discovered local agents). Owners, sponsors and blueprints come from Entra Agent ID; licence context from subscribedSkus.

It cannot read UnifiedAgentObservability. That is a Microsoft Sentinel / Log Analytics data-lake table (fed by the Agent 365 Sentinel connector), and Log Analytics has no browser CORS — it needs a backend. The agent-activity signal that is reachable in-browser is CloudAppEvents (Defender hunting), which the Monitoring layer will use. Shadow-AI detection is read from AgentsInfo; the admin-center Shadow-AI traffic tiles are GSA/portal-only.
