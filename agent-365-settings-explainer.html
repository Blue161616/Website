Policy templates

The governance layer for enterprise agents — and the only setting that reaches past the storefront into Entra, Purview, Defender and SharePoint.

Who these govern — the digital worker

A digital worker is an agent the tenant treats as a worker rather than as a feature. It holds its own Entra Agent ID, so it signs in as itself, carries its own permissions, and can be aimed at by policy that names it — Conditional Access, access packages, lifecycle management.

Microsoft’s name for them in the portal is AI teammates: multi-tenant agents built with the Agent 365 CLI/SDK. Each instance needs a Microsoft 365 Frontier for Autopilots license — think of it as an E7 for an agent identity.

The other family has no identity of its own. It runs on its blueprint’s credentials, shared by every instance of that blueprint, so nothing agent-scoped has a sign-in to bite on. Every policy template on this page splits on exactly that line, and so does what the controls in it can actually enforce.

A policy template is not a template for building an agent. It is a governance and security package that defines which controls travel with an agent from the moment it is Activated.

Definition

Publish of a Requested Agent == Activated. Define the baseline once, apply it every time an agent is activated.

Locked, and forward-inherited

Microsoft adds its required defaults to every custom template, including defaults introduced later. A custom template can only ever be a superset of the baseline. A CA policy scoped to all agent identities is auto-selected and cannot be overridden.

Verify in Entra — don't trust the wizard

Usage · the block that never fires

The without identity template deliberately carries _Block Agent Identity next to AgentApprovalStatus = New. Activate an agent without its own identity: the attribute appears on the Agent ID object, the agent keeps working on its blueprint's credentials, and no per-agent sign-in ever hits the block.

The template accepted both controls; only one of them is in the request path.

Gotchas

New activations only. Templates cannot be applied to already-approved agents; edits change future activations.

Enforcement follows identity. If the agent never appears in the sign-in logs, its custom controls are decorative.

Entitlement. Policy templates are not in Microsoft 365 E3/E5 or Business plans — they need Microsoft 365 E7 or the Agent 365 SKU. New Agent 365 purchases since June 1, 2026 require E5/A5/Business Premium or Defender + Purview Suite underneath.

Agent management rules

Bulk, condition-based governance actions. Two Microsoft rules today, plus custom rules.

Install Microsoft agents defaultInstalls Microsoft-published agents for all users. Only agents not already installed via license entitlement and not blocked by an admin.
Reassign ownerless Agent Builder agents to manager defaultReassigns to the previous owner's manager so every agent has an accountable owner. Agent Builder only

Custom rules

Conditional governance rules that automatically apply an action when conditions match. Actions: Block, Reject publish requests, or Apply template.

Why it matters

This is the bridge to policy templates: instead of an admin picking a template at each activation, a rule matches agents by condition and applies the template on its own. Policy-based governance, not per-agent review.

User access

Control which users or groups can interact with agents.

All users defaultSubject to existing app policies and user assignments.
No usersNobody in the organization can access agents.
Specific users or groups demoUsers who can install agents from the Agent Registry can only use them if they are in this setting.
Usage · User A vs User B

User A (not in the setting) has no Agents section in the Copilot portal. User B (in the setting) sees the published agents.

EU warning

Microsoft warns that data processed by non-Microsoft services isn't covered by Microsoft agreements. That is the GDPR/NIS2 reason "All users" is the wrong default for EU tenants.

Scope

This control applies only to agents built with Copilot Agent Builder. It does not govern Copilot Studio — Copilot Studio has its own governance controls in Power Platform.

Tags

Labels that admins and users apply to agents to organize and find them.

  • Up to 50 tags per organization, each with an optional description
  • Both admins and users can apply them
  • Deleting a tag removes it from every agent that uses it — check the count first
Usage

Add a tag, apply it, then open the Tags overview to see the per-tag agent count.

Agent feedback sharing

Whether thumbs-up / thumbs-down and comments reach the agent's developer.

No agentsDevelopers receive no feedback.
All agents demoDevelopers receive feedback for every agent.
Selected agentsOnly the agents you pick.

Does not affect whether people can rate agents or what data an agent can access.

Usage

A user reacts inside the agent; reactions appear in the agent's Monitor section, visible to the developer.
