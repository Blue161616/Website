App-Only Permission Tester Lab

The counterpart to the delegated tester: this shows an app reading a tenant unattended, as itself, with an application permission (e.g. Directory.Read.All) and a client credential — no user signs in. A browser can't run the client-credentials flow (it needs a secret and the token endpoint blocks CORS), so you get the token in your terminal (where the secret belongs) and paste it here to watch the unattended read and decode the claims.
Prerequisite: your app registration must have Directory.Read.All (or User.Read.All) as an Application permission with admin consent granted in the target tenant, plus a client secret. That is exactly the “publisher holds the key” arrangement — treat the secret and the resulting token as sensitive.

1 · Build the client-credentials request

Fill in the tenant and app, copy a snippet, run it in your terminal, and paste your client secret where marked. It returns an app-only access token.
The secret never touches this page — it stays in your terminal. The token this returns is a short-lived (≈1 h) app-only bearer token.

2 · Paste the app-only access token

Paste the access_token from the snippet's response. It's decoded and used locally — sent nowhere except Microsoft Graph.

Token claims — the app itself, no user

roles = the application permissions this token carries · appid = the app · tid = the tenant it reads · and note there is no scp/upn/name — no signed-in user.

Attack-impact preview — what this credential reads unattended

Enumerates the breadth this app-only token can read in this tenant — with no user involved at all, on the app's credential alone. For a CISO demo: this is what the publisher (whoever holds the secret) reads silently, forever, until you revoke the app. Nothing here leaves your browser — read-only, sent only to Microsoft Graph.
Contrast: the delegated tester needed a user to sign in and was capped by that user's privileges. Here there is no user — the app reads tenant-wide on its own, limited only by the application permissions granted to it. That's why admin-consenting app-only permissions to a third-party app is a standing-key decision.
