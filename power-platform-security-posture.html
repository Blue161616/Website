3
Tenant access

Delegated tokens act as the signed-in user, so permissions alone grant nothing — the account needs the role too.

  • Power Platform Administrator or Global Admin, for the tenant-wide environment list.
  • A Dataverse security role in each environment you want scanned. One you cannot read is skipped silently, which looks like a clean result rather than a missing one.
4
Tenant DLP — export it, nothing to grant

DLP cannot be read from this page, and no role fixes that. It lives only on the legacy admin API (api.bap.microsoft.com), which custom app registrations cannot be granted delegated access to — it is not in the API picker, and the Power Platform API has no DLP permission. Browsers block it via CORS regardless. Being Global Admin grants the authorisation but never the token.

Nothing to grant here. Export it instead — the command and the file picker are under Tenant DLP policies on the right, where you use them. Without it the baseline is computed excluding DLP gaps and may read better than reality.

Coverage is limited to environments where your account has a Dataverse security role.
The browser cannot read tenant DLP (see left). Run this once as a Power Platform / Global admin, then drop dlp.json below:
Install-Module Microsoft.PowerApps.Administration.PowerShell -Scope CurrentUser
Add-PowerAppsAccount
Get-DlpPolicy | ConvertTo-Json -Depth 10 | Set-Content dlp.json
It stays in this browser, and turns the DLP finding from a guess into a per-environment answer. It is a point-in-time copy — re-export after any policy change.
Read-only. Runs entirely in your browser against the Dataverse Web API and (best-effort) the Power Platform admin API. Tenant DLP / governance is attempted and degrades gracefully if the browser blocks it.
