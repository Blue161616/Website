What is Work IQ?

Work IQ is Microsoft's organizational knowledge & reasoning layer — the intelligence over Microsoft 365 (mail, files, chats, meetings, people, org structure) that lets Agent 365 agents reason over your work data and context. Agents reach that data through Work IQ tools/MCP servers on the signed-in user's behalf (OBO) — so an agent's real data reach is the operating user's own access, a surface that application-permission scans cannot see.

How reach is determined (and its limits)
Work-IQ reach is read from each agent's tools / MCP servers / connectors (Defender AgentsInfo, optional) and from its Graph data-read permissions (own + blueprint-inherited). Because Work IQ runs OBO, the true reach is the operating user's access — this tool shows the surface (which domains an agent can touch), not per-user entitlements. Sensitivity-label reach needs InformationProtectionPolicy.Read; Conditional-Access containment needs Policy.Read.All. Everything degrades gracefully.

Three ways an attacker reaches Work IQ data

Work IQ makes data easy to retrieve — which is exactly why it makes a compromise more valuable. Three paths lead to the same place: your work data, surfaced in seconds.

1 · A compromised user — Work IQ as a retrieval accelerant

Work IQ runs on-behalf-of the user (OBO), so whoever controls a user's session controls their Work IQ reach. A phished login used to mean hunting through mailboxes and sites by hand — now the attacker just asks in natural language and Work IQ retrieves across everything that user can see.

Contain: phishing-resistant MFA + risk-based Conditional Access, token / session protection, and Purview DLP-for-AI to limit what Work IQ surfaces to a risky session.

2 · Prompt injection — the agent turns on you

No account compromise needed. The LLM — not the user — decides when a tool fires, so untrusted content the agent reads (an email, a document, a web page) can instruct it to collect data via Work IQ and push it out through an egress tool.

Contain: remove egress / web tools where not needed, treat all retrieved content as untrusted, require human approval for outbound actions, apply DLP to the agent context. The Exploitation view lists your agents that complete this chain.

3 · A compromised blueprint — one key, every agent

The blueprint is the security boundary — it holds the credentials and impersonates its agents. Compromise the blueprint (a leaked client secret, or abuse of its impersonation) and you don't get one agent — you get every agent under it, and each one's Work IQ reach.

Contain: certificates / managed identity instead of client secrets, scope the blueprint's inheritable permissions to least-privilege, monitor blueprint service-principal sign-ins. See the Blueprint Security Posture tool for the blast radius.
